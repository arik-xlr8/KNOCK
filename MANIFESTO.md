# KNOCK - Artist's Manifesto

This project is built around a simple rule: whatever the user writes, the system should try to turn that exact prompt into a visual form. If the user writes "bear," the work should move toward a bear. If the user writes "door," it should move toward a door. If the user writes "badge," it should become a badge-like mosaic. I do not want the AI to replace the user's prompt with Bob Dylan, a singer, a cowboy, or a historical figure. The user's word is the center of the work.

The artwork uses a 16x16 grid, which means the image is made from exactly 256 CSS tiles. Each tile is a small HTML element styled with CSS. Together, the tiles form a pixel-like mosaic. This grid is important because it creates a visible limitation. Instead of asking AI to generate a perfect illustration, the project asks AI to make 256 small decisions: which tiles are active, what color they should be, how intense they are, and how they should contribute to the silhouette.

I chose this medium because it keeps the artwork between language and image. A prompt begins as text, then the LLM translates it into a tile plan, and finally the browser turns that plan into a CSS composition. The result is not a normal image file. It is a constructed image made from code. This makes the process visible and understandable. The viewer can see that the picture is not magic; it is built from pieces.

The project uses two different AI techniques. The first is LLM-based mosaic planning. The language model receives the prompt and returns a JSON structure for the 256 tiles. The second is text-to-image generation. The same prompt is also sent to an image model, which creates a visual reference. The generated image is not the main artwork. It is shown beside the CSS mosaic so the viewer can compare two different AI interpretations of the same prompt.

The main artwork is the CSS mosaic. I made this choice because a ready-made generated image can easily become too complete. A tile mosaic is more fragile and more open. It imitates the subject, but it never fully becomes it. The viewer has to complete the image mentally. This is especially interesting for a project about thresholds, because a threshold is never fully resolved. It is the space between what is known and what is about to happen.

The connection to Bob Dylan's "Knockin' on Heaven's Door" is handled through ready-made prompt buttons and the broader idea of a threshold. The interface includes prompts such as "door," "badge," "heaven's door," and "farewell." These words come from the song's world: the door, the badge, the act of letting go, and the feeling of standing before an ending. However, the AI is not forced to generate Dylan-related imagery for every prompt. If the user writes "bear," the subject should stay a bear.

This separation matters. The assignment asks for historical and cultural context, but that does not mean every generated image should become a portrait of Dylan or a western scene. For me, the stronger idea is to let the song provide a conceptual frame while still respecting the user's input. The song becomes a set of optional symbolic doors. The user may choose one of them, or they may bring another word to the same system.

What caught me most in the song is the line about the badge. A badge is small, but it can carry identity, duty, guilt, authority, and exhaustion. In the original song, the speaker can no longer use it. That feeling of no longer being able to carry something is at the heart of the project. A tile mosaic is also a kind of burden made visible: many small pieces gather into a form, and the form carries meaning.

The year 1973 also matters. "Knockin' on Heaven's Door" belongs to the world of *Pat Garrett & Billy the Kid*, but it also resonates with a wider historical atmosphere shaped by the Vietnam War, anti-war counterculture, and distrust of authority. I do not represent that context by forcing war images into every output. Instead, I keep the symbolic vocabulary available through prompts like "badge," "door," and "farewell." The user can activate that context when they choose those words.

This makes the project more honest to the interaction. If the prompt is "bird," the system should try to make a bird. If the prompt is "heaven's door," then the system moves directly into the song's symbolic space. The historical context becomes a set of meaningful options rather than a filter that distorts every image. I think this is a better way to respect both the user's prompt and the assignment theme.

The 256-tile structure also gives the project a stronger visual language than the earlier 64-tile version. With 64 tiles, the forms were very rough. With 256 tiles, the mosaic still feels pixelated, but it can suggest more detail. A bear can have ears and a face. A door can have panels. A badge can have a recognizable outline. The image remains abstract, but it becomes easier to read.

At the same time, 256 tiles are still limited enough to keep the work from becoming just another generated image. The tiles are visible. Their edges matter. Their small failures matter too. If the mosaic is imperfect, that imperfection becomes part of the experience. It reminds the viewer that meaning is being assembled, not simply delivered.

The project is also about translation. The user translates an idea into a prompt. The LLM translates the prompt into a grid plan. The browser translates the grid plan into CSS tiles. The image model translates the same prompt into a reference picture. These translations do not always agree, and that disagreement is interesting. Sometimes the CSS mosaic may be more symbolic, while the generated image is more illustrative. Sometimes the generated image may be clearer, while the tile mosaic feels more like an icon.

For me, the emotional center of the work is still the act of knocking. The button is not only a UI control. It is the action that activates the threshold. The user writes a word and knocks. The system answers by assembling 256 small pieces. The answer may be an animal, an object, a door, or a word from the song. But the important thing is that the prompt becomes visible.

"Knockin' on Heaven's Door" is a song about an ending, but it is also about recognition. The speaker recognizes that the badge can no longer be used. In my project, the user recognizes their prompt as an image. That recognition can be playful, but it can also become personal. A user may type "bear" just to test the system, but they may also see it as fear. Another user may type "badge" and think about responsibility. Another may type "farewell" and think about transition.

The project does not claim to explain the song. Instead, it borrows the song's central gesture: approaching a door. Every prompt approaches a different door. Some are directly connected to Dylan's imagery; others are not. But all of them pass through the same act of transformation from word to image.

In the end, KNOCK - 256 Tile Prompt Mosaic is a small machine for making prompts visible. It uses AI, but it does not hide behind AI. It uses image generation, but it does not make the generated image the whole artwork. It uses Dylan's song, but it does not force Dylan into every output. The work asks a simple question: if your word had to become 256 tiles, what shape would it take?

This question is important because prompts are usually treated as instructions. In this project, I want the prompt to feel more like a material. A word is not only a command sent to a model. It is something that can be cut, rearranged, colored, and rebuilt. When the prompt becomes a mosaic, the user sees it as an object. The word leaves the input box and becomes a visible structure.

I also like that the project can move between playful and serious uses. Someone can write "bear" and enjoy watching the tiles imitate an animal. Someone else can press the "badge" or "farewell" button and move closer to the song's emotional world. The same system can handle both situations because it is based on transformation rather than explanation. It does not lecture the viewer about what the prompt means. It lets the prompt take form.

The ready-made buttons are therefore not decorative shortcuts. They are small invitations into the assignment's historical context. "Door" points to the central metaphor. "Badge" points to the line about removing a role that can no longer be carried. "Heaven's door" points to mortality and the unknown threshold. "Farewell" points to the emotional tone of the song. These prompts allow the project to remain connected to Dylan without corrupting unrelated user prompts.

This balance matters to me as a creative decision. If every image became Dylan, the user's input would lose power. If the Dylan context disappeared completely, the project would become a generic prompt visualizer. The solution is to separate the two layers: free prompt generation on one side, song-inspired prompt choices on the other. The user decides when to enter the song's symbolic space.

Finally, the tile grid makes the project feel performative. The image does not simply appear; it assembles. The viewer can sense the system arranging pieces into a silhouette. This assembly echoes the act of meaning-making itself. We rarely understand a symbol all at once. We build it from fragments, memories, references, and personal associations. The 256 tiles make that process visible.

The updated interface also includes a Bob Dylan song selector. This selector does not paste long copyrighted lyrics into the work. Instead, each song opens a small set of lyric-inspired visual prompts. For example, "Knockin' on Heaven's Door" offers prompts such as a heavy badge, a glowing door, and a farewell silhouette. "Blowin' in the Wind" offers wind, a dove, and an open road. These prompts help the viewer enter the historical and poetic space of Dylan's music without forcing every free prompt to become Dylan-related.

During image generation, the screen is intentionally blocked by a centered loader. This is a practical interface decision, but it also has a conceptual meaning. The user has knocked, and the system is answering. The waiting moment becomes part of the experience: the prompt is being translated, the image is being generated, and the final reference is being sampled into a 16x16 grid. When the loader disappears, the 256 tiles have assembled a response.

This final version therefore has three layers of authorship. The user chooses or writes a prompt. The AI translates that prompt into a visual reference. The browser reduces that reference into a mosaic made of CSS tiles. The result is not a perfect copy of the image, and it is not meant to be. It is a second interpretation, a coded echo of the generated image. That echo is where the artwork lives.

The Dylan context switch strengthens this structure without weakening the freedom of the prompt. When it is enabled, the visual generation still follows the user's subject. A bear remains a bear; a bird remains a bird; a badge remains a badge. The contextual layer appears beside the mosaic as artwork notes. These notes connect the subject to threshold, badge and burden, farewell and mortality, and the historical atmosphere of 1973. This allows the project to satisfy the assignment's cultural requirement without turning every image into the same Dylan-themed scene.

For me, this separation is important. The image is the user's word made visible, while the notes are the song's memory entering the room. One layer protects the prompt; the other layer interprets it. Together, they make the project more honest: it can be open to any prompt while still carrying the philosophical DNA of "Knockin' on Heaven's Door."

In the final interface, the AI-generated image appears before the artwork notes. This order matters. The viewer first sees the reference image, then the 256-tile CSS transformation, and only then reads the contextual explanation. The work therefore begins with visual experience and moves toward interpretation, rather than forcing the interpretation first.
